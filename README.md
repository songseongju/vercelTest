# DEAD SIGNAL · LAST FIELD (v3.1)

Babylon.js 기반 3D 배틀로얄. v3.0부터 초대 코드로 2~8명 개인전에 참가할 수 있습니다. 멀티플레이 실행·Vercel 설정은 [MULTIPLAYER.md](MULTIPLAYER.md)를 참고하세요. 아래 설명은 싱글플레이 기준입니다. 플레이어 1명과 적 봇 12명이 전투합니다. 무기를 파밍하고 좁아지는 자기장을 피해 마지막까지 살아남으면 승리합니다.

## 플레이

- 무기 없이 시작하며, 시작 지점 바로 앞에 소총·탄약·구급팩·방탄복이 있습니다.
- 아이템 가까이에서 설정된 획득 키(기본 E) 또는 모바일 획득 버튼·아이템 카드으로 파밍합니다. 벽 너머 물건은 획득할 수 없습니다.
- AR-4 돌격소총, V-9 기관단총, DMR-7 지정사수소총을 찾아 보유하고 교체할 수 있습니다.
- 모든 총기는 공용 예비 탄약을 사용하며 탄창은 무기별로 보존합니다.
- 방탄복은 총탄 피해의 65%를 내구도 한도 안에서 흡수합니다. 자기장 피해는 방탄을 무시합니다.
- 치료는 3초 걸리며 구급팩 1개로 체력 65를 회복합니다. 사격하거나 총에 맞으면 치료가 취소됩니다.
- 적은 플레이어와 다른 봇을 발견하면 사격하며, 엄폐물에 가로막히면 우회하고 안전구역으로 이동합니다.
- 미니맵: 파란 원은 현재 자기장, 흰 원은 다음 안전구역, 삼각형은 내 위치입니다.
- 자기장은 반경 78m에서 50 → 30 → 15 → 4 → 0m로 줄어듭니다. 대기·축소를 합쳐 265초 후 완전히 닫힙니다. 구역 밖 피해는 단계에 따라 증가합니다.
- 일시정지하면 전투·자기장·치료·재장전 타이머도 멈춥니다.

## 조작

| 동작 | PC | 모바일 |
|---|---|---|
| 이동 | WASD, Shift 질주 | 왼쪽 패드 |
| 조준 | 마우스 | 오른쪽 영역 드래그 |
| 발사 | 왼쪽 클릭을 누르고 있기 | 발사 버튼 |
| 확대 조준 | 오른쪽 클릭 유지 | 조준 버튼 |

| 재장전 | R | 재장전 버튼 |

| 무기 교체 | 1 / 2 / 3 또는 Q | 교체 버튼 |
| 일시정지 | Esc 또는 Ⅱ | Ⅱ |

포인터 잠금이 불가능한 브라우저에서는 누른 채 드래그해서 조준할 수 있습니다. 시작/일시정지 화면에서 터치·마우스 조작, 선명·성능 화질, 사운드를 전환할 수 있습니다.

## 실행 및 Vercel 배포

싱글플레이는 정적 파일만으로 실행할 수 있습니다. 멀티플레이는 Node.js 서버와 배포 시 Redis 설정이 필요합니다. Vercel Framework Preset은 Other, Root Directory는 이 저장소, Build Command는 `npm run build`, Output Directory는 `dist`입니다.

로컬: `python3 -m http.server 8000` 후 http://localhost:8000 접속.
모바일: 배포된 HTTPS 주소를 Safari 또는 Chrome에서 여세요. iOS 카톡 첨부파일 미리보기 실행은 지원하지 않습니다.

## 파일

- index.html / style.css: 화면 및 모바일 조작 UI
- game.js: 전장, 이동·충돌·AI·사격·파밍·미니맵
- rules.js: 자기장 일정, 인벤토리, 피해·치료·재장전 규칙
- vendor/: 로컬 Babylon.js 엔진 및 라이선스
- star-dash.html: 기존 아케이드 게임

## 검증 및 범위

실제 Babylon.js의 NullEngine으로 파밍, 사격·재장전, 벽과 출입구의 시야 차단, 이동 충돌, 적 사격, 자기장 피해, 승패와 재시작을 검사했습니다. 별도 규칙 테스트로 5단계 축소·탄약 보존·방탄·구급팩 소비를 검사했습니다. 브라우저에서 PC와 모바일 가로 화면을 확인했습니다. 실제 iOS 하드웨어 테스트는 아직 하지 않았습니다.

이 게임은 간단한 로우폴리 그래픽의 오리지널 프로토타입입니다. PUBG/배틀필드의 코드·모델·음악을 사용하지 않으며 v3.0에는 2~8명 온라인 개인전 프로토타입이 포함됩니다.


## v2.1 인체 캐릭터

- 상자형 적을 텍스처와 관절이 있는 Vanguard 인체 모델로 교체했습니다.
- 이동 속도에 따라 대기·걷기·달리기를 전환합니다. 각 봇은 독립된 애니메이션과 뼈대를 갖습니다.
- 두 팔을 총의 손잡이에 맞추는 자세 보정과 사격 반동, 처치 시 넘어짐을 추가했습니다.
- 머리 판정은 애니메이션의 머리 위치를 따라갑니다. 시신은 더 이상 피격되지 않고 정리됩니다.
- 시작 화면에서 캐릭터를 볼 수 있고, 모델 로딩이 끝나야 게임을 시작할 수 있습니다. 실패 시 안내를 표시합니다.
- 모델 약 2.1 MB와 glTF 로더 약 0.7 MB가 추가됩니다. 텍스처와 형상은 봇끼리 공유합니다.
- 출처와 사용 조건: assets/NOTICE.md. 실제 GLB를 로딩하는 테스트로 12개 뼈대 분리, 포즈, 머리 판정, 재시작 시 애니메이션 누수 방지와 전투 규칙을 확인했습니다.

- 방탄 조끼: 어깨끈, 버클, 탄창 주머니와 방탄섬유 텍스처. 탄약 상자도 금속 표면과 손잡이를 갖습니다.

- `controls.js`에서 localStorage에 저장합니다. 웹뷰가 저장을 차단하면 이번 실행에 적용하고 안내합니다.
- 검증: 390×844 / 844×390 브라우저 화면, 드래그 저장 및 새로고침 복원, 카드·버튼을 통한 실제 무기/탄약 획득, 중복 키 차단, 설정 시 일시정지. 단위 검사로 취소·가로세로 분리·저장소 차단·손상 데이터 복구를 확인했습니다. 실제 iOS 기기 검증은 별도입니다.

## v2.2.1 모바일 시작 및 진단

- 모바일은 기본 성능 모드(DPR 최대 1, 그림자 끔, MSAA 끔)로 시작합니다. 화질 버튼으로 해상도·그림자를 올릴 수 있습니다.
- `?safe=1`은 PC에서도 성능 모드로 시작합니다.
- `boot.js`가 가벼운 로딩 화면을 먼저 표시하고 스크립트를 순서대로 로드합니다. 파일 오류·실행 오류·90초 로딩 초과·WebGL 연결 중단에 안내와 재시도 링크를 표시합니다. OS가 탭 자체를 종료하는 경우에는 이 안내도 표시할 수 없습니다.
- `diagnostics.html`은 게임 엔진을 로드하지 않고 파일 응답, 브라우저 정보, 사용자가 요청한 소형 WebGL 그리기를 검사합니다. 진단 결과를 외부로 전송하지 않습니다.
- 회전·주소 표시줄 변경 시 3D 화면 크기 변경을 180ms 모아 처리합니다.
- Vercel 배포 v2.2의 파일은 로컬과 일치하고 HTTP 200임을 확인했습니다. 실제 iPhone의 흰 화면 원인은 아직 확정하지 못했습니다. v2.2.1은 실행 부담 감소와 원인 확인을 위한 보강입니다.

## v3.0 멀티플레이

`npm ci && npm start` 후 http://127.0.0.1:8780 에서 **친구와 플레이**를 선택합니다. Vercel에서는 Redis 연결이 필요합니다(`REDIS_URL` 또는 Upstash REST). 자세한 배포·검증 범위는 [MULTIPLAYER.md](MULTIPLAYER.md)에 있습니다.

## v3.1 그래픽과 입력 안정화

- 촬영 기반 CC0 1K 재질: 아스팔트, 흙·풀, 콘크리트, 나무껍질, 부식된 금속.
- 실제 하늘 HDR을 이용한 배경·반사광, PBR 표면, ACES 색 보정.
- 창틀·문틀·배수관, 잎 실루엣, 총열·레일·방아쇠울 디테일.
- 모바일/가벼운 모드는 작은 환경 맵·낮은 해상도·그림자/노멀맵 해제로 부하를 줄입니다.
- PC 포인터 고정 중 포인터 캡처를 호출하던 사격 오류를 수정했습니다. 터치 캡처 거부·해제도 복구합니다.
- Redis Cloud 등의 `redis://` 연결 문자열과 Vercel KV/Upstash REST 변수 이름을 모두 지원하며, 연결 진단이 실제 Redis 응답을 확인합니다.

전용 고밀도 건물·총기·손 애니메이션을 제작한 실사급 게임은 아닙니다. 기존 공유 맵과 플레이 규칙을 유지하면서 재질·광원·외형을 개선한 단계입니다. 새 환경 에셋은 약 9MB이며, 성능 모드는 노멀맵을 처음부터 받지 않습니다. 출처는 `assets/NOTICE.md`에 있습니다.
